# Экономика AI-стартапа: как не разориться на LLM API

LLM-технологии сделали возможным запуск AI-стартапа буквально за несколько дней.  
Однако большинство разработчиков очень быстро сталкиваются с одной проблемой:

> **инференс моделей стоит дорого.**

Если на обработку одного пользователя требуется несколько LLM-запросов, стоимость может легко превысить доход с этого пользователя.

Поэтому AI-стартапы — это не столько про модели, сколько про **оптимизацию экономики**.

---

# 1. Главная формула AI-стартапа

Любой продукт должен сходиться по **unit-economics**.

Основная формула:

```

LTV > CAC + Inference Cost + Infra Cost

```

где:

- **LTV (Lifetime Value)** — средний доход с пользователя  
- **CAC (Customer Acquisition Cost)** — стоимость привлечения пользователя  
- **Inference Cost** — стоимость работы моделей  
- **Infra Cost** — сервера, хранение данных, сеть

Если:

```

доход с пользователя = 3 ₽

```

то желательно, чтобы:

```

стоимость инференса < 1 ₽

```

иначе экономика не работает.

---

# 2. Почему инференс становится главной проблемой

LLM API обычно оплачиваются **за токены**.

Даже относительно дешёвые модели могут давать ощутимые расходы.

Пример сценария:

```

1 пользователь
→ 5–10 запросов к LLM
→ каждый запрос ~500–1500 токенов

```

В результате стоимость обработки пользователя может составить:

```

1–5 рублей

```

Если доход меньше — стартап работает в минус.

---

# 3. Каскад моделей (основная стратегия экономии)

Большинство успешных AI-сервисов используют **каскад моделей**.

Идея:

```

cheap model → cheap model → expensive model

```

То есть:

1. дешёвая модель выполняет простые задачи  
2. дорогая модель используется **только когда действительно нужна**

Пример pipeline:

```

user input
↓
cheap LLM (классификация)
↓
rules / embeddings
↓
cheap LLM (генерация)
↓
expensive LLM (если требуется)

```

В хорошей архитектуре **90% запросов никогда не доходят до дорогой модели**.

```

Claude Haiku

Mistral small
Qwen

```

Некоторые из них стоят:

```

$0.05 – $0.20 за миллион токенов

```

Это **в десятки раз дешевле топовых моделей**.

---

# 5. Убивайте LLM-запросы где возможно

LLM должен быть **последним инструментом**, а не первым.

Перед тем как отправлять запрос в модель, стоит попробовать более дешёвые методы.

### Rule-based логика

```

regex
фильтры
словари
простые правила

```

### Embeddings + поиск

```

vector search
semantic matching

```

### Шаблоны

Многие ответы можно генерировать из заранее подготовленных шаблонов.

---

# 6. Кэширование

Во многих продуктах большое количество запросов повторяется.

Можно использовать кэш:

```

hash(input) → ответ

```

Это позволяет:

```

снизить расходы на 30–60%

```

---

# 7. Сокращение токенов

Токены — главный источник расходов.

Частая ошибка:

```

очень длинные prompt

```

Пример:

```

плохой prompt = 5000 токенов
оптимизированный = 300–500 токенов

```

Экономия может достигать **10–20 раз**.

---

# 8. Batch inference

Если система позволяет, полезно обрабатывать запросы **пакетами**.

Это позволяет:

```

снизить стоимость инференса
ускорить обработку

```

---

# 9. Локальные LLM

Ещё один путь оптимизации — **self-hosted модели**.

Плюсы:

```

нулевая стоимость токенов
контроль инфраструктуры
приватность

```

Минусы:

```

нужен GPU
сложность поддержки
обновления моделей

```

Типичный сервер для инференса:

```

RTX 4090
A100
или аналогичный GPU

```

Такие сервера обычно начинают окупаться при больших объёмах:

```

> 5–10 млн токенов в день

```

# 11. Агентные системы — опасная зона

Многие AI-проекты строят системы, где один запрос запускает:

```

10–20 LLM вызовов

```

Это может полностью разрушить экономику продукта.

Хорошая цель:

```

1–3 LLM вызова на пользователя

```

Часто стоимость лида:

```

5–50 рублей

```

Это может быть дороже самого инференса.

# 16. Этапы развития AI-стартапа

Обычно развитие проходит через три этапа.

### Этап 1 — MVP

```

быстро сделать продукт
использовать готовые API
не думать сильно об оптимизации

```

### Этап 2 — оптимизация

```

cheap models
caching
prompt optimization
pipeline улучшения

```

### Этап 3 — масштабирование

```

self-hosted inference
собственная инфраструктура
оптовые закупки токенов

```

# 17. Главный вывод

AI-стартап — это не просто использование моделей.

На практике успех определяется:

```

экономикой
архитектурой
оптимизацией
маркетингом

```

LLM — это лишь один из компонентов системы.

---

# Итог

Чтобы AI-стартап был прибыльным, необходимо:

```

минимизировать число LLM вызовов
использовать дешёвые модели
оптимизировать prompt
кэшировать ответы
использовать каскад моделей

```

Если всё сделать правильно, можно снизить стоимость обработки пользователя **в десятки раз** — и сделать проект экономически жизнеспособным.
```
